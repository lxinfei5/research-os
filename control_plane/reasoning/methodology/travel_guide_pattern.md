# Travel Guide Research Pattern

> 旅游攻略类研究的方法论：如何搜、如何评、如何排。与 L0–L3 知识分层无关，
> 是一套独立的"消费决策辅助"研究模式。

---

## 0. 一句话

旅游攻略的产出是**用户可直接用的消费决策**（去哪、吃啥、住哪），不是知识卡片。
因此评价体系必须**以社媒活人评价为准**，公开平台评分仅做参考。

---

## 1. 核心原则：社媒优先

```
社媒活人评价（小红书/抖音） > 公开平台评价（大众点评/Trip.com） > AI 生成内容
```

**为什么**：大众点评和 Trip.com 的评分体系容易被商家控评（刷好评、删差评、投广告换排名）。
社媒上的活人吐槽无法被商家删除，是**不可控的真实信号**。

**工具选择**：
- 小红书 → `xiaohongshu-mcp`（必须走有头模式，无头模式会被 XHS 风控拦截）
- 抖音 → `webbridge-mcp`（天然有头——跑在用户真实 Chrome 里）
- web → `web-search-prime` + `web-reader`

**判断标准**（权重从高到低）：
1. 带具体菜品/具体槽点的长文评论（如"酿豆腐的馅太少，只有指甲盖大"）
2. 多平台交叉出现的同一条好评/差评（如小红书和抖音都在骂服务差）
3. 带图的差评（图不会说谎）
4. 纯打分（如"4.5 分"）——仅作参考，不单独用于排序

---

## 2. 产出结构：吃、住、行

### 2.1 吃（最重点）

每个餐厅必须给出：
- **评分**（综合各平台）
- **好评摘要**（≥3 条，来自社媒活人，带点赞数/互动量）
- **差评/槽点摘要**（≥2 条，来自社媒活人，带点赞数/互动量）
- **人均消费**
- **距核心景点的距离/车程**
- **综合排序**：按"好评密度 − 差评严重度"排序，不是按星级

**搜索策略：两阶段，第二阶段逐候选人执行。**

Phase 1 — 发现候选（宽搜）：
```
搜 "<目的地> 美食 推荐" → 产出候选餐厅列表（N 个名字）
```

Phase 2 — 逐候选差评审计（N 组独立搜索，不可合并）：
```
对列表中的每一个候选餐厅，单独发起差评搜索：
  搜 "<餐厅名> 踩雷"
  搜 "<餐厅名> 难吃"
  搜 "<餐厅名> 态度差"
  搜 "<餐厅名> 不值得"
```
> **禁止**搜"惠州 难吃的餐厅"这种泛查询——泛查询只会返回 SEO 软文，
> 真正的活人差评一定带店名。N 个候选 = N 组差评搜索，每组互相独立，
> 可以并行发起但搜索词必须是 `<店名> + 负面词`。

Phase 2 产出的信号分为两档：
- 🔴 **硬伤**：卫生问题、短斤缺两、食材不新鲜（有图为证）→ 直接降级或排除
- 🟡 **体验槽点**：服务差、排队久、环境吵 → 降权重但不排除，标注在结果中

**注意**：如果某餐厅 Phase 2 零结果（完全没有差评），要警惕——可能是新店或控评严重。在最终表格中标注 `⚠️ 差评样本缺失`。

### 2.2 行（路线+景点）

每条路线给出：
- **具体景点/村子名** + 可导航地址
- **可玩性**（一句话，不要废话）
- **社媒活人评价**（好+差，各 ≥1 条，带来源平台）
- **是否有门票/收费**

路线数量：3 条左右，用一个对比表呈现，不要长篇展开。

### 2.3 住

简短推荐即可：
- 给出 2–3 个选项
- 标注位置、价格区间、特色（一句话）
- **不做深度评价**（住宿体验主观性太强，样本太少无法可靠排序）

## 3. HTML 输出规范

### 3.1 设计风格

参考 `methodology/travel_visual_style.md`（TravelOS DESIGN.md）的极简原则：
- 单栏，最大宽度 800px
- 白底 + 细灰线 + 绿色点缀（`#3d6b4f`）
- 无渐变、无动画、无阴影堆叠
- 表格为主，卡片为辅
- PingFang SC 字体

### 3.2 必须包含地图

使用 **Leaflet + OpenStreetMap**（CDN 加载，需联网查看地图）：

```html
<link rel="stylesheet" href="https://unpkg.com/leaflet@1.9.4/dist/leaflet.css" />
<script src="https://unpkg.com/leaflet@1.9.4/dist/leaflet.js"></script>
<div id="map" style="height:400px;border-radius:8px;margin:1.5rem 0;"></div>
```

地图标注内容：
- 🟢 绿色标记 = 景点/村子
- 🟠 橙色标记 = 餐厅
- 🔵 蓝色标记 = 住宿
- 路线用折线连接（不同路线不同颜色）

坐标从搜索中获取（景点/餐厅一般有明确地址可查经纬度）。

### 3.3 文件落点

```
topics/<slug>/plan.html
```

---

## 4. 质量自检清单

生成后 agent 必须逐条确认：

- [ ] 每个餐厅都有 ≥3 条好评摘要 + ≥2 条差评摘要
- [ ] 每个餐厅的差评来自**独立的逐候选搜索**（不是泛搜"XX地难吃"）
- [ ] 差评不是敷衍的"一般般"，而是有具体内容的
- [ ] 排序不是按星级，是按综合好评密度−差评严重度
- [ ] 路线对比表存在且 ≤4 条
- [ ] 地图已嵌入，标记点坐标大致准确
- [ ] HTML 文件已在浏览器中打开（`open <path>`）
- [ ] 没有大段 AI 味描述（如"身心放松、流连忘返"）
